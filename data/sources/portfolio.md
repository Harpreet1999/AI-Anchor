## Projects

### Agentic AI Grounding Platform
*Full Stack · Enterprise · AI* — React, Vite, Node.js, Express, AWS Lambda, PostgreSQL
Summary: A Streamlit prototype proved the idea worked — the harder question was how to make it something an enterprise team could actually rely on. Rebuilt natively in React with serverless AWS Lambda processing.
- **Problem**: The Streamlit prototype proved the underlying idea worked, but Streamlit itself wasn't something an enterprise team could build a production workflow on top of — no real component ownership, limited state control, and no clean path to a serverless backend.
- **Approach**: Rebuilt the interface natively in React from scratch, including the agent-configuration and application-grounding screens, and moved local processing into AWS Lambda functions to get to a serverless, horizontally scalable backend.
- **Outcome**: The platform now runs as a real internal product rather than a prototype demo — easier to maintain, easier to scale, and owned end-to-end on the front end.
- Architecture: Frontend React + Vite; Backend Node.js/Express + AWS Lambda (serverless); Database PostgreSQL; Deployment AWS.
- Key features: Agent-configuration screens for application grounding; serverless AWS Lambda processing pipeline; native React UI replacing the Streamlit prototype; built for enterprise-grade reliability and maintainability.

### Case Evaluation Intelligence Agent
*AI Agent · Life Sciences* — React, Streamlit, REST APIs, AI Agent Interfaces
Summary: The agent could evaluate cases correctly — the open question was how to make that legible to stakeholders who had to trust it enough to sign off. Built the UI and shaped the client-facing demo prototypes.
- **Problem**: The AI agent could evaluate cases correctly, but a correct answer isn't useful if the people who have to sign off on it can't see why the agent reached it — trust was the actual blocker, not accuracy.
- **Approach**: Owned the client-facing half of the agent — the UI, the REST API integration back to the model, and the prototypes used live in stakeholder demos — focused on making the agent's reasoning legible rather than just its output.
- **Outcome**: Demos now walk stakeholders through the agent's reasoning, not just its conclusion — which is what actually moved sign-off conversations forward.
- Architecture: Frontend React; Backend REST API integration to the evaluation model; Deployment Internal.
- Key features: Reasoning-first UI that shows why the agent reached a conclusion; REST API integration to the evaluation model; client-facing demo prototypes used live in stakeholder sessions.
